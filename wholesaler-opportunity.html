Definitions

Segment & Metric Definitions

Core + eShop
Wholesalers with Komet Core system AND at least one active eShop (buyer-facing storefront). These can sell via eCommerce, API, and K2K channels.
Core + API (sells via API)
Wholesalers with Komet Core that sell online via API channel. Includes major accounts like Mayesh (API-heavy), KBC, BDC. Note: $25.1M API GMV from 3 accounts pays $0 in API fees.
Core (online no API, no eShop)
Wholesalers with Komet Core that sell online (via eCom or K2K) but do NOT have an eShop or API sales.
Core (offline only)
Wholesalers with Komet Core that had ZERO online sell-side activity in the period. All their GMV flows through offline channels (phone, walk-in, standing orders entered manually).
K2K + eShop
Wholesalers connected via K2K (Komet-to-Komet network) that also have an eShop. 100% of their sell GMV is online (K2K is inherently digital).
eSuite
Wholesalers using the eSuite product (lightweight digital suite). Fee type = "Gross Profit Share" (distinct from eCom/API/K2K fees).
K2K only
Wholesalers connected via K2K network WITHOUT an eShop. Can sell and buy through K2K but do not have a buyer-facing storefront. Sell-side note: we only see online GMV. Total business estimated from SFDC Annual_Total_Sales where available.
Procurement only
Wholesalers that ONLY buy through Koronet Procurement. They do not sell on the platform via Core. They generate $0 direct fees but create INDIRECT fees on the vendor side. Sell-side note: we only see K2K sales. Total business estimated from SFDC.
Other / Unknown
Wholesalers in Koronet with no clear classification or minimal/no activity in the period. May include churned accounts or data quality issues.
# Vendors Total / Online / Offline (BUY columns)
Total: distinct vendors this segment buys from (any channel). Online: vendors bought from via Procurement or Web channel. Offline: vendors bought from via Unknown or N/A channel.
Buy Online / Buy Offline (BUY columns)
Online: Procurement + Web + API channels in PROCUREMENT_DETAILS. Offline: Unknown + N/A channels. Source: PROCUREMENT_DETAILS + COMPANIES + VENDORS, ks_flag=TRUE.
# Buyers H1 / L30D (SELL columns)
Buyers H1: distinct customer_id in SALE_DETAILS for H1 period, online channels only (eCom + API + K2K), dump accounts excluded. L30D: subset active in last 30 days. Source: SALE_DETAILS, ks_flag=TRUE, sales<100K.
Est. Total Rev (SFDC)
For segments without Core (K2K only, Procurement only, eSuite): Snowflake only sees their online GMV. SFDC Annual_Total_Sales__c gives their estimated total business size. Coverage: 55 of 104 non-Core accounts have data (47% NULL). This is a floor, not ceiling.
Sell by Channel
Breakdown of online sell GMV by channel: eCom = eCommerce, K2K = Komet-to-Komet, API = API integrations. Source: SALE_DETAILS, sales_channel field.
"Online" (Sell Side)
eCom + API + K2K channels. Per channels.json (authoritative source). Excludes offline channels (phone, walk-in, standing orders entered manually).
"Online" (Buy Side)
Procurement + Web + API channels. Buying through the digital procurement system. Per channels.json.
"Indirect Fees" (K2K Commissions)
Fees generated on K2K transactions. The SELLER pays the K2K commission.
